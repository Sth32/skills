# Game Development Skills

一组面向游戏研发需求与实现协作的 Agent Skills。它把口述需求逐步收敛为可配置、可实现、可评审、可维护的工程结果，同时保持策划、服务端与客户端的职责边界。

## 工作流

```text
原始材料
  ↓
01 原始需求
  ↓
02 需求挖掘（面向策划）
  ↓
03 程序实现澄清（面向负责程序）
  ↓
04 配置规划与配表
  ↓
05 数据与消息拓扑骨架
  ↓
06 完整实现
  ├─ 客户端对接文档（属性 / RPC 合同，按需生成或更新）
  ↓
07 多 Agent 交叉评审
  ↓
项目长期功能文档
```

这些是可组合动作，不是不可逆的瀑布阶段。新事实改变上游决策时，应更新对应文档，而不是在下游堆补丁。

## 技能

| 技能 | 主要产物 | 负责解决的问题 |
|---|---|---|
| `game-spec` | `01-原始需求.md` | 将口述、聊天、工单和各类文档无损压缩为简洁的原始需求 |
| `game-discovery` | `02-需求挖掘.md` | 基于需求与现有代码，向需求负责人确认真正影响产品规则的遗漏点 |
| `game-tech-clarify` | `03-程序实现澄清.md` | 向负责程序收敛高影响架构、数据、兼容和失败处理决策 |
| `game-config` | `04-配置规划.md` | 用差异优先的短文档确认配置对象、真实配置源、关键值和修改范围，再配表并验证 |
| `game-scaffold` | `05-框架实现方案.md` + 可运行骨架 | 确定实体属性、数据权威与持久化、镜像同步、客户端可见性和空 RPC 路由，不实现产品规则 |
| `game-implement` | `06-完整实现方案.md` + 完整代码 | 沿已确认框架补齐行为、边界、失败、兼容、测试和运维闭环 |
| `game-client-handoff` | `客户端对接文档.md` | 从 Server 事实生成属性同步、实体生命周期、RPC/事件和数据充分性合同，不设计客户端内部实现 |
| `game-review` | `07-交叉评审.md` | 使用独立多 Agent 视角交叉证伪需求、配置、架构和实现问题 |
| `game-docs` | `docs/features/<feature>.md` | 将实际实现提炼为短小、稳定、以代码导航和坑点提醒为主的长期文档 |

默认过程文档目录：

```text
docs/requirements/<feature>/
├── 01-原始需求.md
├── 02-需求挖掘.md
├── 03-程序实现澄清.md
├── 04-配置规划.md
├── 05-框架实现方案.md
├── 06-完整实现方案.md
├── 客户端对接文档.md（按需）
└── 07-交叉评审.md
```

`game-config` 只有在用户明确要求手动填表交接材料时，才额外生成 `04-配置执行清单.md`；字段级执行细节不进入主规划文档。

`game-client-handoff` 可在属性和 RPC 骨架稳定后先生成草稿，并在完整实现后根据实际协议、同步路径和错误语义更新；它不占用过程文档编号。

长期实现文档优先服从项目已有约定；没有约定时写入：

```text
docs/features/<feature>.md
```

## 设计原则

1. **文档是工作面**：问题、答案、状态、方案与证据写回对应文档，聊天只承载当前交互。
2. **事实自己查，决策才问人**：代码、配置和历史实现能回答的事实，不转嫁给策划或程序。
3. **按影响收敛**：只讨论会改变行为、范围、架构、数据安全或交付风险的事项。
4. **逐层保持职责**：原始需求不扩展；需求挖掘不设计技术；框架阶段不实现产品规则；对接文档不设计客户端内部实现；长期文档不复制代码。
5. **运行安全优先**：不完整功能可以受控关闭，但不得破坏服务器启动、资产、数据和其他系统。
6. **证据优于结论**：配置需导表和加载验证，实现需测试和运行证据，对接文档需与实际属性、协议和同步代码一致，review 需触发路径和代码依据。
7. **允许回退上游**：发现根因性错误时修订原决策，不以下游补丁维持错误框架。

## 安装

```bash
npx skills@latest add Sth32/skills
```

也可以只复制需要的 `skills/<skill-name>/` 目录到 Agent 的 skills 目录。

## 验证

运行静态验证：

```bash
python scripts/validate_skills.py
```

`evals/` 中包含每个技能的行为测试场景，用于检查需求丢失、越界提问、危险占位、无证据完成、对接合同缺失、review 锚定和文档过度细化等失效模式。

## 参考思想

本仓库吸收以下项目的方法，并按游戏研发中“策划—程序—配置—实现—维护”的协作边界重新设计：

- `mattpocock/skills`：小型、可组合技能；事实通过环境调查获得；决策逐个确认。
- `Fission-AI/OpenSpec`：以可更新工件承载迭代过程，不把真实开发伪装成单向阶段。
- `obra/superpowers`：先理解与确认，再进入实现；按依赖推进；使用行为场景验证技能本身。
