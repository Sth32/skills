# Game Development Skills

一组面向游戏研发需求协作的 Agent Skills。目标不是替代策划或程序做决定，而是把需求从口述与散乱材料，逐步收敛为可追踪、可确认、可实现的文档。

## 技能

| 技能 | 产物 | 负责解决的问题 |
|---|---|---|
| `capturing-game-requirements` | `01-原始需求.md` | 将口述、聊天、工单和各类文档无损压缩为简洁的原始需求 |
| `discovering-game-requirements` | `02-需求挖掘.md` | 基于需求与现有代码，向需求负责人确认真正影响产品规则的遗漏点 |
| `clarifying-game-implementation` | `03-程序实现澄清.md` | 基于已确认需求与代码架构，向负责程序收敛高影响实现决策 |

默认目录：

```text
docs/requirements/<feature>/
├── 01-原始需求.md
├── 02-需求挖掘.md
└── 03-程序实现澄清.md
```

## 设计原则

1. **文档是唯一工作面**：问题、答案、状态和衍生结论都写回对应文档，聊天只用于当前一轮交互。
2. **事实自己查，决策才问人**：代码、配置、历史实现能够回答的事实，不转嫁给策划或程序。
3. **按决策价值提问**：只问答案会改变行为、范围、架构、数据安全或交付风险的问题。
4. **逐层收敛**：原始需求不做扩展；需求挖掘不讨论实现；程序澄清不重新定义产品目标。
5. **允许迭代，不允许失控**：每轮回答后重新判断问题是否解决、是否产生新问题，并淘汰低价值分支。

## 安装

仓库发布到 GitHub 后，可使用兼容 Agent Skills 的安装器安装整个仓库，或直接复制单个 `skills/<skill-name>/` 目录到所用 Agent 的 skills 目录。

```bash
npx skills@latest add Sth32/skills
```

## 验证

运行静态验证：

```bash
python scripts/validate_skills.py
```

`evals/` 中包含每个技能的行为测试场景。它们用于验证 Agent 是否会丢失需求、越界提问、提出低价值问题或过早结束采访。

## 参考思想

本仓库吸收了以下项目的核心方法，但按游戏研发中“策划—程序”职责边界重新设计：

- `mattpocock/skills`：小型、可组合技能；事实通过环境调查获得；决策逐个确认。
- `Fission-AI/OpenSpec`：以可更新的工件承载迭代过程，而不是依赖线性阶段和聊天上下文。
- `obra/superpowers`：先理解与确认，再进入实现；问题按依赖顺序推进；技能本身需要可验证的行为契约。
