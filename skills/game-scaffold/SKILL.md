# 搭建游戏功能实现框架

## 目标

先让整体实现框架定型：明确模块边界、核心数据结构、主流程和安全的未完成边界；经用户确认后实现可运行骨架，并维护 `05-框架实现方案.md`。

**核心原则：这一阶段交付的是“可继续完成且不伤害现有系统的骨架”，不是伪装成完整功能的半成品。**

## 前置条件与产物

必须读取：

- `01-原始需求.md`；
- `02-需求挖掘.md`；
- `03-程序实现澄清.md`；
- `04-配置规划.md`；
- 相关代码、配置、测试、架构约定和启动方式。

若仍有会改变架构方向的未解决 P0/P1 问题，先返回对应技能处理。

默认写入：

```text
docs/requirements/<feature>/05-框架实现方案.md
```

使用 [框架实现方案模板](references/框架实现方案模板.md)。

## 本阶段应该定型的内容

- 功能归属和模块责任；
- 核心实体、持久化数据、状态与关键不变量；
- 主流程、入口、出口和跨模块契约；
- 配置读取与校验边界；
- 失败隔离、开关、降级和未完成功能的安全表现；
- 后续细节应落在哪些扩展点；
- 证明服务器和其他系统不受影响的最小验证方式。

本阶段不追求：

- 穷举所有边界分支；
- 完成所有业务算法、奖励细节和运营工具；
- 大量局部重构、命名优化和非必要抽象；
- 为未来假设提前建设通用框架。

## 工作流程

### 1. 建立当前基线

先确认：

- 相关模块当前职责和可复用路径；
- 服务器启动、构建、导表和测试基线；
- 本次允许修改的代码与配置范围；
- 公共接口、持久化格式和跨进程契约；
- 现有功能中不能被改变的行为。

基线已失败时，记录并区分既有问题，不把它误认为本次实现结果。

### 2. 产出简洁框架方案

方案必须展示：

1. **模块图**：新增/修改模块及责任，不列无关文件；
2. **核心数据结构**：关键字段、所有权、生命周期和不变量；
3. **主流程**：正常路径及少量关键失败出口；
4. **接口契约**：谁调用、输入、输出、幂等或状态要求；
5. **配置连接**：`04-配置规划.md` 中数据如何进入运行时；
6. **安全边界**：哪些细节暂缓、暂缓时系统如何稳定运行；
7. **骨架验证**：启动、注册、加载和隔离测试。

优先使用短表格、伪代码或 Mermaid。不要把方案写成逐函数施工清单。

### 3. 区分“框架决策”和“延期细节”

只有影响后续大部分代码的内容才在本阶段定型，例如：

- 数据归属、状态模型、模块边界和公共接口；
- 同步/异步主路径；
- 事务、一致性和失败隔离的基本策略；
- 配置模型和兼容策略。

可以延期：

- 低影响边界行为；
- 不阻塞主流程的运营辅助能力；
- 局部算法优化和低风险性能优化；
- 已有明确扩展点承载的次要分支。

延期项必须写明后续落点，不能只写“以后处理”。

### 4. 确认后再实现

向用户展示框架方案、核心数据结构、主流程和延期项，明确请求确认。

用户未确认前：

- 可以调查、写方案、画流程和准备验证命令；
- 不创建正式业务代码，不修改公共接口、数据格式或注册链路。

确认后，只按已确认框架实施。发现方向性矛盾时暂停并修订方案，不用局部补丁掩盖。

### 5. 实现可运行骨架

骨架通常包括：

- 模块、服务或组件的基本边界；
- 核心类型、数据模型和序列化结构；
- 配置加载和启动期校验；
- 入口、路由、事件或协议注册；
- 主流程编排和明确的扩展点；
- 必要的日志、错误类型和最小可观测性；
- 能证明接线正确的 smoke test 或最小集成测试。

只实现建立框架所需的业务逻辑。不要在骨架阶段顺手完成大量细节。

### 6. 安全处理未完成内容

允许内部功能暂时不完整，但必须满足：

- 服务器可构建、导入、启动和正常关闭；
- 未完成功能不会在启动时抛出致命异常；
- 不产生半写入、错误扣除、重复发奖或不可恢复状态；
- 对外入口默认关闭、受功能开关保护，或返回明确且可控的未开放结果；
- 不改变其他功能的成功路径和数据；
- `TODO`、占位实现和临时分支均有明确归属，并记录在文档中；
- 不以空 catch、静默吞错或伪造成功来维持“能跑”。

涉及持久化或资产时，宁可在写入前拒绝，也不要执行不完整流程。

### 7. 验证并回写实际状态

至少验证：

- 标准构建、静态检查和服务器启动；
- 配置可加载，缺失或错误配置能受控失败；
- 新入口关闭或未完成时行为安全；
- 现有关键功能的 smoke test 不受影响；
- 数据结构可序列化/反序列化，旧数据兼容策略成立；
- 实际代码边界与方案一致。

将已实现框架、验证证据、延期项和任何偏差回写 `05-框架实现方案.md`。

## 完成条件

- 用户已确认框架方案；
- 模块、核心数据、主流程和接口边界已经定型；
- 服务器可以正常运行，其他系统不受影响；
- 未完成内容全部可见、受控且没有危险副作用；
- 后续可在不推翻框架的情况下完成细节；
- 文档明确说明“已完成骨架”和“待完整实现”的边界。

## 常见错误

| 错误 | 正确处理 |
|---|---|
| 方案还未确认就开始大规模编码 | 先展示框架、数据和流程并获得确认 |
| 为了“能跑”吞掉所有异常 | 对未完成入口受控拒绝，保留真实错误 |
| 骨架阶段实现所有细节 | 只完成决定整体形状的部分 |
| 留空逻辑仍然写入资产或状态 | 在任何副作用前阻断 |
| 新模块启动即强依赖不完整数据 | 使用校验、开关或安全默认关闭 |
| 实际代码偏离方案但不更新文档 | 暂停、修订并重新确认方向性变化 |
