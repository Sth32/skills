# 完成游戏功能实现

## 目标

基于已确认并可运行的框架，补齐需求细节、失败路径、兼容与验证；先产出并确认 `06-完整实现方案.md`，再完成代码。

**核心原则：沿既定框架完成行为闭环；发现框架根因问题时修订框架，不在细节层堆补丁。**

## 前置条件与产物

必须读取并核对：

- `01-原始需求.md`；
- `02-需求挖掘.md`；
- `03-程序实现澄清.md`；
- `04-配置规划.md`；
- `05-框架实现方案.md`；
- 已实现骨架、当前 diff、测试和启动结果。

若骨架不能安全运行，先回到 `scaffolding-game-implementation` 修复，不在不稳定基线上继续扩展。

默认写入：

```text
docs/requirements/<feature>/06-完整实现方案.md
```

使用 [完整实现方案模板](references/完整实现方案模板.md)。

## 工作流程

### 1. 验证框架仍然成立

开始前检查：

- 实际模块、数据结构和主流程是否与 `05` 一致；
- 延期点是否仍可在既定扩展点内完成；
- 是否出现会推翻数据归属、公共接口或状态模型的新事实；
- 配置、旧数据和上下游是否仍满足原决策；
- 服务器基线和骨架验证是否通过。

局部差异可在完整方案中说明。若需要推翻核心边界，修订 `05` 并重新确认，不要把重新设计伪装成细节实现。

### 2. 建立需求到代码的完成矩阵

逐条对照已确认需求，把每项标为：

- 已由骨架完成；
- 本阶段需要实现；
- 明确延期或不在范围；
- 被配置、外部系统或既有代码满足；
- 当前存在矛盾或缺少决策。

只有真实需求和高价值安全项进入实现，不为“看起来完整”增加无来源能力。

### 3. 产出完整实现方案

方案按依赖顺序描述剩余工作，至少包含：

- 核心规则和状态转换的完整行为；
- 配置字段如何影响流程；
- 权限、资格、次数、消耗、奖励和重复操作；
- 持久化、并发、幂等、事务和跨进程时序；
- 失败、重试、补偿、取消和恢复；
- 旧数据、旧协议、灰度、开关和回滚；
- 日志、指标、告警和运维入口；
- 测试层级、关键场景和完成证据。

保持方案可审阅。描述决策和行为，不粘贴大段最终代码。

### 4. 确认后开始完整实现

向用户展示：

- 剩余工作范围；
- 重要边界和风险；
- 与骨架相比是否有方向变化；
- 实现批次及验证方式；
- 仍建议延期的项目。

获得确认前不开始大规模细节编码。用户只确认部分范围时，明确剩余项状态，不默认全部获批。

### 5. 按纵向闭环实现

每个批次应形成可验证的行为闭环，而不是按文件类型横向铺开：

1. 完成一组相互依赖的规则；
2. 补齐数据与配置使用；
3. 完成失败和副作用边界；
4. 添加或更新测试；
5. 运行相关验证；
6. 再进入下一组。

优先完成主流程，再处理高影响边界。不要同时留下多个无法运行的半成品分支。

### 6. 清除骨架阶段的临时边界

逐一处理：

- `TODO`、`NotImplemented`、临时返回和默认关闭入口；
- 占位数据、硬编码测试值和临时配置；
- 仅为骨架存在的兼容分支；
- 缺失的错误处理、日志和指标；
- 未验证的迁移、序列化和回滚路径。

确实延期的内容必须转为显式范围外、任务或受控开关，不能以隐蔽占位留在完成状态中。

### 7. 完整验证

根据风险选择验证层级：

- 单元测试：纯规则、状态转换和不变量；
- 集成测试：配置、存储、消息、协议和跨模块流程；
- 回归测试：受影响的既有系统；
- 启动与升级测试：旧数据、缺省配置、迁移和回滚；
- 并发/幂等测试：资产、次数、重复请求和跨进程操作；
- 故障测试：超时、部分失败、重试和补偿；
- 性能验证：仅在真实容量风险存在时执行。

不能运行的验证要说明原因、替代证据和剩余风险，不能写成“应该没问题”。

### 8. 回写实际完成状态

更新 `06-完整实现方案.md`：

- 需求完成矩阵；
- 实际实现和与方案的偏差；
- 测试与运行证据；
- 仍延期或范围外内容；
- 已知风险和后续 review 重点。

## 完成条件

- 已确认范围内的需求行为全部有实现或明确的外部承载；
- 骨架中的危险占位和隐式未完成逻辑已清除；
- 配置、数据、接口、失败、兼容和回滚形成闭环；
- 关键测试和服务器运行验证通过；
- 不再存在未标记的 P0/P1 实现风险；
- 文档与实际代码一致，可进入交叉 review。

## 常见错误

| 错误 | 正确处理 |
|---|---|
| 在既定框架上不断打局部补丁 | 发现根因性边界错误时修订框架 |
| 按文件批量写完后再集成 | 按行为闭环分批实现和验证 |
| 把未完成 TODO 留在“完成”代码中 | 实现、明确延期或受控移出范围 |
| 只测试成功主流程 | 覆盖资产、状态、失败、重试和兼容 |
| 方案写得很细但没有需求追踪 | 建立需求到代码的完成矩阵 |
| 无法执行测试却宣称完成 | 记录限制、替代证据和剩余风险 |
