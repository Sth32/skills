# 规划并修改游戏配置

## 目标

识别需求中真正应该配置化的内容，选择现有表或新表，完成已确认的文本配置修改，并维护简洁的 `04-配置规划.md`。

**核心原则：主文档是配置决策摘要，不是逐字段填表说明书。执行方式按配置源分别决定；Excel 选择手动，不等于其他文本配置可以不做。**

## 前置条件与产物

必须读取：

- `01-原始需求.md`；
- `02-需求挖掘.md`；
- `03-程序实现澄清.md`；
- 项目的配置源、导表工具、生成物、加载代码和同类配置。

默认主产物：

```text
docs/requirements/<feature>/04-配置规划.md
```

使用 [配置规划模板](references/配置规划模板.md)。已有文档时原位更新。

只有用户明确要求提供手动填表交接材料时，才额外生成：

```text
docs/requirements/<feature>/04-配置执行清单.md
```

使用 [配置执行清单模板](references/配置执行清单模板.md)。它是执行辅助，不是长期方案文档。

## 主文档长度契约

`04-配置规划.md` 的目标是 **40–80 个非空行**，并且只保留四类信息：

1. 配置结论；
2. 配置对象、目标表与各自执行方式；
3. 需要用户或负责人确认的高影响事项；
4. 实际修改与验证结果。

超过 80 个非空行时，必须删除重复、合并同类对象，或把执行细节移入可选清单。只有新增复杂表结构时才允许例外，并需说明超长原因。复杂不等于可以写成字段百科。

表格单元格使用短语或 1–2 个短句，不在一个单元格中堆放完整行定义。

## 什么应该配置化

优先考虑：

- 策划或运营需要调整的数值、文本、奖励、概率、时间、阈值和开关；
- 与已有配置实体自然对应的映射、分组、阶段或规则参数；
- 不同环境、活动、赛季或版本可能变化的值；
- 需要被导表校验、客户端或多个服务共同消费的数据。

通常保留在代码中：

- 算法结构、状态机拓扑、协议语义和不可变业务约束；
- 局部实现常量、运行时值、缓存键和技术参数；
- 没有明确维护者、无法安全调整或配置后更难理解的内容。

判断依据是变化责任和生命周期，不是“它是不是数字”。

## 信息优先级

### 必须写入主文档

- 哪些内容需要配置，哪些关键内容保留代码；
- 目标文件、Sheet 或表，以及复用还是新建；
- 每个配置源的格式、执行方式和当前状态；
- 新增或修改的配置对象；
- 来自需求的关键数值、标识和跨表引用；
- 会改变表结构、消费端或发布范围的决定；
- 当前真正阻塞配表的未决项；
- 实际修改、未修改原因和验证结论。

### 仅在影响决策时写入

- 主键和行粒度；
- 单位、空值和默认值语义；
- 导表、热更、客户端同步和迁移影响；
- 复用现有表的理由；
- 保留代码的高影响边界。

### 禁止写入主文档

- 从参照行复制而来、此次不需要改动的全部字段；
- 每个单元格的填写步骤；
- 项目已有且本次没有变化的完整导表链路；
- 所有默认值、展示字段、图标字段和普通布尔字段的穷举；
- 同一事实同时出现在摘要、明细、范围和结果四处；
- 与配置无关的完整代码任务清单；
- 长篇调查过程、命令输出和验证日志。

需要这些信息时，引用参照行、代码路径、diff 或日志位置，不把内容复制进主文档。

## 混合配置执行契约

一个需求可能同时涉及 Excel 与 YAML、JSON、Lua、Python、CSV、INI 或其他文本配置。**执行方式必须按配置源分别确认和跟踪，不得设置一个覆盖全部文件的全局“手动/自动”状态。**

对每个配置源记录：

- 文件、Sheet 或表；
- 格式；
- 计划修改对象；
- 执行方式；
- 当前状态；
- 验证结果。

必须遵守：

1. 用户选择“Excel 手动配置”，只表示 Agent 不直接修改 Excel 源文件；
2. 该选择不撤销、不延期、不覆盖文本配置的修改范围；
3. 文本配置范围尚未确认时，单独请求确认，不要把它混入 Excel 手动/自动问题；
4. 文本配置范围已经确认时，Agent 必须继续修改真实文本配置源、展示 diff 并执行必要校验；
5. 用户只回答“手动”且上下文问题是“Excel 手动还是自动”时，只按 Excel 手动处理，不得推断所有配置都改为人工；
6. 任何已确认由 Agent 修改的文本配置仍处于“待配置”时，不得宣告 `game-config` 完成，也不得直接进入 `game-scaffold`；
7. 只有用户明确排除、撤销或要求仅输出方案时，才可以不修改已识别的文本配置，并必须记录原因。

## 工作流程

### 1. 调查但不倾倒调查结果

确认配置源格式、真实源文件、同类表、主键、引用、导表方式、生成物和消费端。

调查用于做决定。除非它改变配置方案，否则不要把配置系统全貌写进 `04-配置规划.md`。不要直接修改可再生生成物。

### 2. 提取并筛选配置候选

将候选分为：

- **必须配置**：维护责任、变化频率或跨端消费要求配置化；
- **建议配置**：有现实调整价值，但首版可固定；
- **保留代码**：配置收益低于复杂度和误配风险。

“保留代码”只列会影响后续实现边界的少数事项，默认不超过 3 条。不要把所有非配置规则重新抄一遍。

### 3. 建立配置源执行矩阵

在询问执行方式前，先穷尽本需求涉及的配置源，至少检查：

- Excel/CSV 表格；
- YAML、JSON、Lua、Python、INI、XML、文本 DSL 等文本配置；
- 新表、Schema、生成规则或加载注册；
- 客户端与服务端是否存在不同源文件。

不能因为主要数值位于 Excel，就停止搜索同一功能的文本开关、类型注册、资源映射、路由、白名单或模块列表。

将每个目标加入配置变更清单，并分别标记：

- `待确认`；
- `文本直接修改`；
- `Excel 手动`；
- `Excel 自动`；
- `明确不改`；
- `已完成`。

### 4. 选择目标表或文件

优先复用同领域、同行粒度、同生命周期和同维护者的现有表或配置文件。

只有出现以下情况才考虑新表或 Schema：

- 行粒度或主键明显不同；
- 需要独立发布、复用、校验、版本或迁移；
- 放入现有表会造成大量空字段、重复行或跨域依赖；
- 现有表会因此承担第二种职责。

新表或导表结构变化必须单独确认。

### 5. 按“差异”写配置规划

配置清单默认 **一行对应一个目标表、Sheet、文件或配置实体**，而不是一行对应一个字段。

每行只写：

- 要新增或修改什么；
- 关键字段和值；
- 关键引用或参照对象；
- 格式、执行方式和状态；
- 尚未确定且会阻塞执行的事项。

可使用这样的表达：

> 复制望楼 1046 的两行结构，新建会盟坛 1050；仅调整 ID、元素引用、名称、消耗、耗时和耐久，其余字段沿用参照行。

不要把参照行的全部字段再次列出。需求已明确的数值直接写，项目默认值只在它影响产品或安全时写。

### 6. 分别确认直接修改范围

一次性展示所有计划修改的源文件、Sheet/表、配置对象、格式和建议执行方式。

按源格式处理：

- **文本配置**：单独确认可直接修改的文件范围；范围确认后必须完成修改、展示精确 diff，并运行格式或加载校验；
- **Excel 配置**：必须询问用户选择“手动配置”还是“自动配置”；
  - 手动：不改 Excel，但不影响已确认文本配置的继续执行。只有用户明确要求交接清单时，才生成 `04-配置执行清单.md`；
  - 自动：先备份并保留格式、公式、验证和合并单元格，完成后给出紧凑变更摘要；
- **新增表或修改导表结构**：必须单独确认。

用户未确认某一配置源时，只暂停该源；其他已确认配置源继续执行。

### 7. 修改并验证

按执行矩阵逐项处理：

1. 修改所有已确认由 Agent 处理的真实文本配置源；
2. 自动 Excel 才修改 Excel；手动 Excel 保持待人工状态并提供必要差异；
3. 运行项目标准导表、格式检查或生成流程；
4. 检查类型、主键、引用、枚举、范围和生成物 diff；
5. 验证服务器或消费端能够加载；
6. 将每个配置源的结果压缩回写主文档。

验证部分默认不超过 5 条，只写“执行了什么、是否通过、失败原因、剩余风险”。完整日志保留在原位置并提供路径。

## 完成前压缩与执行检查

交付前逐项检查：

- 能否在一分钟内看出要改哪些配置源、关键值是什么、还缺什么决定；
- 是否为每个配置源分别记录了格式、执行方式和状态；
- Excel 手动是否错误地导致文本配置被跳过；
- 是否仍有已确认的文本配置停留在“待配置”；
- 是否一行字段可以改写为“参照对象 + 变化字段”；
- 是否重复解释了导表链路、手动方式或已确认状态；
- 是否列出了不变字段或完整行定义；
- 是否把真正的 P0/P1 未决项埋在文末；
- 是否可以删除一半文字而不损失配置决策。

任一答案不理想，先修正再交付。

## 完成条件

- 关键需求配置项都有配置化或保留代码的结论；
- 所有潜在配置源均已调查，不因 Excel 是主配置而遗漏文本配置；
- 目标表、文件与关键差异清楚；
- 每个配置源都有独立执行方式和状态；
- 用户已确认文本修改范围及 Excel 手动/自动方式；
- 所有已确认由 Agent 修改的文本配置均已完成并通过必要验证；
- 自动执行的配置通过必要导表和加载验证；
- 手动 Excel 的剩余工作明确且不伪装为已完成；
- 主文档足以作为 `game-scaffold` 的配置契约。

## 常见错误

| 错误 | 正确处理 |
|---|---|
| 用户选 Excel 手动后停止整个配置任务 | 只暂停 Excel 修改，继续完成已确认的文本配置 |
| 把执行方式设置为一个全局状态 | 按文件、Sheet 或配置源分别记录方式和状态 |
| 主要数据在 Excel 就不再调查文本配置 | 继续检查开关、类型注册、资源映射、白名单和模块列表 |
| 文本修改范围已确认但只写方案不落地 | 直接修改真实源、展示 diff、执行校验 |
| 把配置规划写成完整填表教程 | 主文档只写关键差异；手工教程按需放独立清单 |
| 抄出参照行所有字段 | 引用参照行，只列需要改变的字段 |
| 未确认就自动修改 Excel | 必须让用户选择手动或自动 |
| 手改导出生成物 | 修改真实配置源并重新导表 |
