# 配置游戏需求数据

## 目标

识别需求中真正应该配表的内容，结合项目现有导表结构选择目标表或提出新表，并维护 `04-配置规划.md`。

**核心原则：先确定“什么需要配置、配置到哪里”，再确认允许修改的范围；不要把所有常量都变成配置。**

## 前置条件与产物

必须读取：

- `01-原始需求.md`；
- `02-需求挖掘.md`；
- `03-程序实现澄清.md`；
- 项目的配置源、导表工具、生成物和加载代码。

默认写入：

```text
docs/requirements/<feature>/04-配置规划.md
```

使用 [配置规划模板](references/配置规划模板.md)。已有文档时原位更新。

## 配置候选的判断

优先考虑配置化：

- 运营或策划需要在不改代码的情况下调整的数值、文本、奖励、概率、时间、阈值和开关；
- 与已有配置实体一一对应的映射、分组、阶段或规则参数；
- 不同环境、活动、赛季或版本可能变化的值；
- 需要被导表校验、客户端或其他服务共同消费的数据。

通常保留在代码中：

- 算法结构、状态机拓扑、协议语义和不可变业务约束；
- 仅服务于局部实现的内部常量；
- 运行时生成值、缓存键和技术参数；
- 配置后反而更难理解、无法安全热更或没有维护者的内容。

判断标准是“变化责任和生命周期”，不是“它是不是一个数字”。

## 工作流程

### 1. 调查配置与导表链路

先确认：

- 配置源格式：Excel、CSV、YAML、JSON、Lua、Python、文本 DSL 或数据库；
- 表之间的主键、引用、继承、分表和命名规则；
- 导表命令、生成目录、校验器和运行时加载方式；
- 哪些文件是源，哪些是生成物；
- 同类功能现有配置放在哪里，由谁维护；
- 修改配置是否需要同步客户端、重启、热更或数据迁移。

不要直接修改生成物，除非项目明确把它当作源文件。

### 2. 提取并筛选配置项

从已确认需求逐条提取候选项，并分为：

- **必须配置**：变化频率、维护责任或跨端消费明确要求配置化；
- **建议配置**：有实际调整价值，但可在首版固定；
- **保留代码**：配置化收益低于复杂度和误配风险。

每个候选都要追溯到需求规则。不要根据经验额外发明字段。

### 3. 选择目标表

优先复用现有表，但必须同时满足：

- 语义属于同一领域实体；
- 主键和行粒度匹配；
- 生命周期、发布节奏和维护者一致；
- 加载侧与消费侧相同或自然兼容；
- 新字段不会让现有表承担第二种职责。

考虑新表的信号：

- 行粒度或主键模型明显不同；
- 配置独立发布、独立复用或被多个模块消费；
- 塞入现有表会产生大量空字段、重复行或跨域依赖；
- 需要独立校验、版本、分组或迁移；
- 现有表已经难以理解，新增内容会继续扩大错误半径。

新表不是默认答案。必须说明不复用的原因、加载位置和维护成本。

### 4. 先产出配置规划

在任何修改前，写清：

- 配置项、来源规则和用途；
- 数据类型、单位、默认值、范围和空值语义；
- 目标表、目标字段、主键和引用关系；
- 复用现有表或新增表的理由；
- 需要同步的导表、生成物和消费端；
- 风险、校验方式和待确认项。

只记录能改变配置设计或修改范围的内容，不写逐单元格流水账。

### 5. 确认直接修改范围

向用户一次性展示计划修改的源文件、表、字段以及是否需要新增表或导表规则，并请求确认范围。

按源格式处理：

- **文本型配置**：推荐在范围确认后直接修改，并展示精确 diff；用户可明确排除某些文件或只要求方案。
- **Excel 配置**：必须询问“手动配置”还是“自动配置”。
  - 手动：不改 Excel，输出表名、Sheet、主键、字段、目标行和填写规则；
  - 自动：先保留备份，使用能保留格式、公式、数据验证和合并单元格的方式修改，并输出单元格级变更摘要。
- **新增表或修改导表结构**：无论格式如何，都必须单独确认，因为它会扩大代码和发布范围。

用户未确认时，不修改配置源。

### 6. 修改并验证

在已确认范围内：

1. 修改配置源，不手改可再生的输出文件；
2. 运行项目标准导表命令；
3. 检查语法、类型、主键重复、引用完整性、范围和枚举；
4. 检查生成物 diff 是否只包含预期变化；
5. 验证服务器能加载配置，缺省值和旧配置仍可工作；
6. 将实际修改、验证结果和未修改项回写 `04-配置规划.md`。

导表失败时先定位根因，不通过绕过校验或手改生成物完成任务。

## 完成条件

- 每个需求配置项都有“配置化或保留代码”的明确结论；
- 目标表、字段、主键、默认值和引用关系清楚；
- 用户已确认修改范围以及 Excel 的手动/自动方式；
- 已执行的修改通过导表和加载验证；
- 新表或导表改动没有未归属的消费端；
- 文档能作为后续框架实现的配置契约。

## 常见错误

| 错误 | 正确处理 |
|---|---|
| 看到数字就配表 | 先判断变化责任、生命周期和实际维护需求 |
| 为少量字段随意新建表 | 优先检查同领域、同粒度的现有表 |
| 把不相关字段塞进“大杂烩表” | 语义或生命周期不匹配时提出新表 |
| 未确认就自动修改 Excel | 必须让用户选择手动或自动 |
| 直接编辑导出生成物 | 修改真实配置源并重新导表 |
| 只列字段，不验证消费端 | 同时确认加载、引用、默认值和跨端同步 |
