# 复杂配置管线指南

仅在跨多个真实源、涉及 Schema、多目标输出、生成代码或复杂覆盖关系时读取。

## 逻辑配置对象

先定义业务上被共同维护和消费的对象，再列出它的物理组成：

```text
逻辑配置对象
├── 真实数据源
├── Schema/字段/校验声明
├── 数据生成物
├── 类型或访问代码生成物
├── 输出目标
└── 运行时消费端
```

一个对象可以只有一个源，也可以跨多个文件或 Sheet。不要为了模型完整而虚构不存在的阶段。

## 变更层级

- **数据变更**：新增/修改记录、数值、映射或文本；
- **Schema 变更**：新增字段、类型、索引、引用、约束或输出范围；
- **生成管线变更**：修改加载器、生成器、模板或解析逻辑；
- **运行时代码变更**：修改注册、消费、同步、结算或业务行为。

`game-config` 可处理确认后的数据和声明式 Schema；后两类只记录并移交。

## 数据生成与代码生成

不要默认二者总是一起执行：

- 只改数值：通常只需数据生成；
- 新增字段或类型：通常需要数据生成，并可能需要类型/访问代码生成；
- 修改输出范围：检查每个目标的生成物；
- 修改加载协议或生成逻辑：移交实现阶段。

生成后检查 diff 是否与变更层级匹配。只改一个值却产生大面积代码 diff，应暂停调查。

## 输出目标

项目存在客户端、服务端、编辑器或工具输出时，只检查受影响目标：

- 哪些目标需要该对象或字段；
- 服务端专属字段是否泄露到客户端；
- 双端类型或数据是否一致；
- 不相关目标是否保持无变化。

## 多源一致性

同一对象跨 Excel、XML、YAML 等源时：

- 确认主键和引用关系；
- 检查是否存在重复事实和覆盖优先级；
- 分别确认每个真实源的执行方式；
- 生成物只从其真实源更新；
- 运行时代码接线作为后续依赖处理。

## 可重复生成

生成器稳定且执行成本可接受时，可在不修改输入的情况下再次生成。第二次应无新 diff；否则记录生成不稳定问题，不手改输出掩盖。
