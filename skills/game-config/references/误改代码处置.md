# 误改代码处置

仅在 `game-config` 本轮已经修改运行时代码时读取。

1. 立即停止继续补实现，不把半实现扩展成完整功能。
2. 查看 diff，区分本轮 Agent 改动、用户已有改动和其他任务改动。
3. 只有本轮改动范围明确、可独立撤销时，才做精确回退。
4. 不使用整仓 `reset`、整文件覆盖或粗暴 `checkout` 破坏无关改动。
5. 无法安全隔离时，不自动回退；列出文件、符号和精确 diff，请用户决定。
6. 将真正需要的代码工作写入 `04-配置规划.md` 的“后续实现依赖”。
7. 标明应由 `game-scaffold` 还是 `game-implement` 接管，以及完成配置闭环所需验证。
8. 文档记录处置结果：已安全回退 / 待用户处理 / 未发现误改。

不得把误改代码包装成“文本配置已完成”，也不得宣称功能已生效。
