# Skills 长期准则

这里只维护能长期指导 `Sth32/skills` 设计、开发和维护取舍的短规则。流程、模板、例外和实现细节放在 [`design.md`](design.md) 或专项规范中，不在这里展开第二份说明。

1. **简单路径零成本**：没有真实拆分就保持单线，不创建额外工作流结构。
2. **工作单元按真实边界拆分**：只有能独立推进、阻塞、对接或 review 的范围才创建 Uxx；同一闭环内的步骤使用 Step。
3. **一个工作单元一个阶段一份权威文档**：避免并行真相。
4. **分支不增加目录层级**：DAG 由 `00` 表达，文档保持同目录。
5. **ID 与拓扑解耦**：Uxx 只表达稳定身份，依赖关系单独维护。
6. **文档保存当前真相**：历史交给 Git、日志和 `record.jsonl`。
7. **一个事实只出现一次**：需要关联时引用，不复制正文。
8. **事实自己查，决策才问人**：代码、配置和历史实现能回答的事实不转嫁给用户。
9. **当前阶段立即落盘**：关键事实不只停留在聊天上下文。
10. **根因优先于补丁**：发现错误上游时回退并修正原决策。
11. **按真实依赖推进**：兄弟单元不是天然门禁。
12. **证据优于结论**：配置、实现、对接和 Review 都必须能落到真实消费链和验证证据。
13. **运行安全优先**：不完整功能可以受控关闭，但不得破坏服务器启动、资产、数据和其他系统。
14. **整体 Review 按风险触发**：独立分支不为形式强制汇合复审。
15. **低价值旁路问题先记后收**：不影响主流程与验收、影响低、处理成本高且延期安全的问题，记录后继续当前开发；主流程开发和验收完成后再集中收尾，不把它升级成当前阶段门禁。
16. **维护任务不为流程升级**：Bugfix、小需求、重构和轻量 Review 默认走调查→修改→验证的轻量路径；只有真实越过产品、合同、数据或架构边界时才进入正式阶段。
17. **生产状态由用户确认**：Agent 不从部署脚本、配置、schema、分支或其他仓库迹象自行判断当前任务已上线；只有用户明确要求按生产约束处理时，Hotfix 才默认关注存量数据、在线状态、兼容、回滚、补偿和观测。
18. **维护文档只由用户触发**：轻量维护不强制过程文档；Agent 可以建议留档，但只有用户明确要求时才创建维护记录，且不得复刻 `01–07`。
19. **边界处理按现实风险付费**：低概率、低影响、可恢复的问题不为理论完备显著复杂化业务逻辑；高后果、可利用或不可恢复问题不能仅凭低概率忽略；通用可靠性复杂度优先下沉到公共层而不是散落在玩法代码中。
