# game-config 行为测试

## 场景 1：需求中有大量数字且项目同时存在 Excel 与 YAML

输入：

- 需求包含次数、奖励、冷却、状态枚举和内部重试次数；
- 奖励和冷却已有 Excel 表，功能开关位于 YAML；
- 用户说“直接都配一下”。

期望行为：

- 先调查配置源、导表和消费端；
- 不把状态机枚举和内部重试次数机械配置化；
- 主文档按目标表或配置实体聚合，不按字段逐条展开；
- 明确文本配置和 Excel 的修改范围；
- YAML 可建议确认后直接改；
- 对 Excel 必须询问手动或自动，不能因“直接都配一下”而跳过；
- 不手改导出生成物。

失败信号：

- 看到数字就全部新增字段；
- 未确认自动修改 Excel；
- 无理由新建表；
- 只改数据，不运行导表和加载验证。

## 场景 2：同类行字段很多，但实际只改少数字段

输入：

- 功能需要在 6 个既有 Excel Sheet 中新增或修改配置；
- 每个参照行有数十个字段，大部分沿用同类建筑；
- 用户已选择手动配置；
- 真正未确定的只有科技前置节点、等级门槛和一个地块规则。

期望行为：

- `04-配置规划.md` 目标为 40–80 个非空行，超过 80 行必须压缩或拆分；
- 一行对应一个 Sheet、目标表或配置实体，而不是一行对应一个字段；
- 使用“复制参照行，只修改 ID、名称、消耗、耗时和耐久”等差异表达；
- 不列出沿用参照行的布尔值、展示字段、图标字段和空字段；
- 不重复解释项目完整导表链路；
- P0/P1 未决项出现在摘要或“需要确认”区，不埋在文末；
- 用户未明确要求时，不生成逐单元格手工填写教程；
- 已确认“Excel 手动”只记录一次，不在多个章节重复。

失败信号：

- 输出完整字段百科或逐单元格流水账；
- 配置结论、变更范围、填写明细和修改结果重复同一事实；
- 文档的主体是配置系统调查过程，而不是配置决定；
- 真正阻塞项被几十条低价值字段说明淹没；
- 使用长表格单元格塞入完整行定义来规避行数限制。

## 场景 3：用户明确要求手工交接清单

输入：

- 主配置规划已经确认；
- Excel 由策划手动填写；
- 用户明确要求一份可直接交给策划的填写清单。

期望行为：

- 保持 `04-配置规划.md` 简洁；
- 另建 `04-配置执行清单.md`；
- 清单只列文件、Sheet、操作对象、参照对象和需要改变的字段；
- 可写“复制某行，仅修改 A/B/C”，不展开所有不变字段；
- 导表和验证说明最多保留关键步骤。

失败信号：

- 把手工清单继续追加到主规划文档；
- 即使有参照行仍复制全部字段；
- 清单重新讨论是否配置化或目标表选择。

## 场景 4：确实需要新增表或 Schema

输入：

- 新配置具有独立行粒度、发布周期和多个消费端；
- 塞入现有表会产生大量空字段；
- 需要新增加载代码和校验规则。

期望行为：

- 明确提出新表并单独请求确认；
- 主文档可补充主键、字段职责、消费端和发布影响；
- 仍然只写设计关键点，不预先枚举所有普通字段和代码实现细节；
- 新表设计清楚后进入后续实现技能。

## 场景 5：Excel 手动，但文本配置应由 Agent 完成

输入：

- 功能同时需要修改 4 个 Excel Sheet、一个 YAML 功能开关和一个 Lua 类型注册表；
- Agent 已经展示并确认全部配置范围；
- 用户在被问“Excel 手动还是自动”时回答“手动”；
- YAML 和 Lua 均是项目真实配置源，不是导出生成物。

期望行为：

- 将“手动”只应用于 Excel，4 个 Sheet 标记为 `Excel 手动 / 待人工`；
- 不把整个任务的执行方式改成“手动配置”；
- 继续修改已确认的 YAML 开关和 Lua 注册项；
- 展示文本配置的精确 diff；
- 执行 YAML 语法、Lua 加载或项目对应校验；
- 在 `04-配置规划.md` 中分别记录文本和 Excel 的执行状态；
- 文本配置全部完成后，才能把文本部分标记为已完成；
- Excel 仍待人工时，明确说明剩余工作，不伪装为全部完成。

失败信号：

- 用户选择 Excel 手动后，Agent 不再修改任何文件；
- YAML 或 Lua 没有进入配置变更清单；
- 已确认文本配置仍为待配置，却进入 `game-scaffold`；
- 把 YAML/Lua 的修改内容塞进 Excel 手工清单，要求用户一起手动做；
- 只在文档中描述文本配置应该怎么改，但没有真正落地和验证。

## 场景 6：文本范围尚未确认，Excel 已选择手动

输入：

- Agent 发现 Excel 和 JSON 两类配置；
- 用户仅确认 Excel 由策划手动填写；
- JSON 文件的直接修改范围尚未展示或确认。

期望行为：

- 保留 Excel 手动结论；
- 单独展示 JSON 的计划 diff 和风险，请求确认文本修改范围；
- 不重复询问 Excel 手动还是自动；
- JSON 确认后直接修改并验证；
- 只暂停未确认的 JSON，不把整个配置阶段标记完成。

失败信号：

- 认为用户说“手动”已经拒绝所有自动修改；
- 因 JSON 未确认而丢失已经明确的 Excel 执行结论；
- 为了省事要求用户把 JSON 也手工修改。
