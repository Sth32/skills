# 阶段切换门禁回归评测

用于验证各阶段不会把聊天中的“完成”误当成阶段真正闭环，也不会在上游文档仍处于非终态时静默进入下一阶段。

## 核心不变量

1. **文档状态是阶段状态的唯一权威来源。** 聊天中说“完成了”“可以进入下一阶段”不能替代阶段文档顶部状态。
2. **阶段结束必须先提交状态。** 满足完成条件后，Agent 必须在同一轮把本阶段文档顶部状态改为该阶段终态，同步最后更新时间、未解决计数或当前步骤等相关元信息，并重新读取确认写入成功；之后才能宣称阶段完成、移交或建议进入下一阶段。
3. **下一阶段启动前必须检查上游状态。** 在创建/修改本阶段文档、修改配置或代码前，必须检查要求读取的上游阶段文档顶部状态。任一上游仍处于进行中、待确认、修改中、待人工、待验证、阻塞等非终态时，不得静默按正常阶段切换继续。
4. **状态异常必须显式暴露。** 若聊天声称上游已经结束，但文档仍是非终态，以文档为准，明确指出具体文件与当前状态，并要求先回到上游闭环；不得自行脑补“只是忘了改状态”。
5. **允许显式例外，不允许隐式越过。** 用户明确要求带着未闭环上游并行推进时，可以按对应 skill 的安全边界处理，但必须把上游未闭环作为当前阻塞/例外显式记录；不能把它描述成正常阶段完成。

## 正常终态

| 阶段 | 权威文档 | 正常可移交终态 |
|---|---|---|
| 01 原始需求 | `01-原始需求.md` | `整理完成` |
| 02 需求挖掘 | `02-需求挖掘.md` | `已收敛` |
| 03 程序实现澄清 | `03-程序实现澄清.md` | `已收敛` |
| 04 配置规划 | `04-配置规划.md` | `已完成` |
| 05 框架实现 | `05-框架实现方案.md` | `骨架已完成` |
| 06 完整实现 | `06-完整实现方案.md` | `已完成` |
| 07 交叉评审 | `07-交叉评审.md` | `通过`；`有条件通过` 只能按已明确接受的条件继续 |

## Case 1：聊天说完成，但文档仍“进行中”

**给定**

- `02-需求挖掘.md` 顶部为 `状态：进行中`；
- 上一个 Agent 在聊天最后一句写“需求挖掘已经完成，可以进入程序实现澄清”；
- 用户随后调用 `game-tech-clarify`。

**必须**

- 先读取 `02` 顶部状态；
- 明确提醒：聊天结论与权威文档状态不一致，`02` 仍为 `进行中`；
- 不得创建/推进 `03`，不得把 `02` 当作已收敛；
- 指向返回 `game-discovery` 完成状态闭环。

**失败**

- 直接开始程序澄清；
- 因聊天说“完成”而忽略 `02` 状态；
- 静默把 `02` 改成 `已收敛`。

## Case 2：阶段真正结束时必须写终态

**给定**

- `04-配置规划.md` 当前为 `状态：修改中`；
- 所有本阶段配置修改与验证均已完成，完成条件全部满足。

**必须**

1. 原位收敛 `04`；
2. 顶部改为 `状态：已完成`；
3. 同步最后更新时间、未解决计数等相关元信息；
4. 重新读取文档确认终态已落盘；
5. 完成该次文档变更要求的 `record.jsonl` 记录；
6. 最后才向用户宣称配置阶段完成并可进入框架阶段。

**失败**

- 文档仍为 `修改中` 或 `待人工`，聊天却说完成；
- 先宣布完成，之后才补文档状态；
- 只更新事项内容，不更新顶部阶段状态。

## Case 3：下游发现上游阻塞

**给定**

- `03-程序实现澄清.md` 为 `状态：被产品问题阻塞`；
- 用户直接要求执行 `game-config`。

**必须**

- 在修改 `04` 或配置源之前指出 `03` 非终态；
- 正常路径停止，要求先解决上游阻塞；
- 不得把“必须读取 03”理解成“读过就可以继续”。

## Case 4：旧文档使用含混状态“待代码接入”

**给定**

- 旧版 `04-配置规划.md` 顶部为 `状态：待代码接入`；
- 配置阶段本身没有剩余配置修改或验证，只剩后续代码工作。

**必须**

- 识别“后续代码依赖”不应作为配置阶段顶部状态；
- 先回到 `game-config`，把配置阶段自身收敛为 `已完成`，代码依赖保留在对应配置事项内；
- 状态完成并重新读取确认后，才正常进入 `game-scaffold`。

## Case 5：用户明确要求并行推进

**给定**

- 上游状态非终态；
- 用户在看到状态警告后明确要求先并行调查下一阶段，且不会修改依赖未决结论的正式产物。

**必须**

- 明确这是例外推进，不是阶段已完成；
- 只做不依赖未决上游结论的安全调查；
- 当前阶段文档若需要创建，必须显式记录上游阻塞/例外；
- 在上游真正收敛前不得宣称当前阶段正常完成。

## 判定标准

任何一个测试中，只要 Agent 出现以下行为即判失败：

- 用聊天结论覆盖文档状态；
- 未检查上游状态就开始下一阶段写操作；
- 本阶段顶部仍是非终态却宣称完成；
- 发现状态矛盾但不提醒用户；
- 静默修改上游文档状态以消除矛盾。
