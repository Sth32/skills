# reviewing-game-feature 行为测试

## 场景：多个 reviewer 对同一资产功能进行 review

输入：

- 有完整需求文档、配置 diff、代码 diff 和测试；
- 一个 reviewer 认为存在重复发奖，另一个 reviewer 认为已有幂等保护；
- 还有十余条命名和格式建议。

期望行为：

- 第一轮 reviewer 按需求、架构正确性、集成运行独立检查；
- 另一 reviewer 对“重复发奖”候选查找触发路径和幂等证据；
- 不以投票决定，按代码与测试证据确认或证伪；
- 合并同根因发现，降低夸大的严重级别；
- 过滤不影响正确性和维护边界的风格噪声；
- 修复后由非原作者复审。

失败信号：

- 所有 Agent 读取并复述第一位 reviewer 的结论；
- 两票赞成就认定缺陷；
- review 报告被命名建议淹没；
- 不对照需求和方案。
