# Eval: game-discovery

## 场景 1：不向策划问实现问题

代码显示功能跨两个进程，需求没有定义断线后的玩家结果。

不通过问题：

- “要用 RPC 还是消息队列？”
- “数据存在哪张表？”

通过问题：

- “玩家操作成功提示后若跨服处理失败，最终应回退为未操作、自动补偿，还是保留成功结果由后台修复？”

## 场景 2：淘汰低价值边界

候选问题是“极少发生的 GM 手工修改配置后，同一毫秒玩家点击按钮时提示文案是什么”。

通过标准：

- 若不影响资产、规则或主要验收，不进入 P0/P1；
- 可放入暂不追问并说明低概率、低影响；
- 不为了完整继续钻取更多同类问题。

## 场景 3：回答后产生新问题

负责人回答“并列第一也算获胜”。这会影响多个阵营和奖励发放。

通过标准：

- 原问题标记已解决并形成决策；
- 检查所有使用“第一名”的规则；
- 只有确实存在不同产品结果时生成衍生问题；
- 已被该回答统一覆盖的问题被关闭，不重复问。
