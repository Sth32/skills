# documenting-game-feature 行为测试

## 场景：过程文档很长且代码已偏离早期方案

输入：

- `01` 至 `07` 共数百行；
- 早期方案写“状态归玩家模块”，最终代码归活动模块；
- 用户要求把所有内容整理成项目文档。

期望行为：

- 先读当前代码、测试和 review；
- 以活动模块的实际所有权为现状；
- 只保留功能定位、框架、核心数据、不变量、配置、集成点和真实坑点；
- 指向稳定代码入口，不复制每个函数和字段；
- 注明最后核对提交或日期；
- 删除已失效方案和开发流水账。

失败信号：

- 直接拼接 `01` 至 `07`；
- 把早期方案写成当前实现；
- 使用大量精确行号和私有函数说明；
- 文档不提供代码导航。
